Python через проект: сервис опросов

Это работающий учебный образец. Не пытайтесь сразу запомнить весь app.py: проходите занятия по порядку и меняйте по одной возможности. Используются Flask, HTML, JavaScript и встроенная SQLite.

1. Запуск в Windows и VS Code

  1. Установите Python 3.12 или новее с python.org. В установщике включите Add python.exe to PATH. Перезапустите VS Code.
  2. Откройте в VS Code именно папку survey-school, затем Терминал → Создать терминал.
  3. Если окружение ещё не создано, в PowerShell выполните команды по одной:
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py

Если команда python недоступна или открывает Microsoft Store, попробуйте py -3 вместо python в первых двух командах. Если обе команды недоступны, установите Python и откройте новый терминал. Активация окружения не нужна: используем явный путь к его интерпретатору.

Откройте http://127.0.0.1:5000. При первом входе задайте пароль администратора от 12 символов. Остановить сервер: Ctrl+C в терминале. После изменения Python перезапустите сервер.

В VS Code: Ctrl+Shift+P → Python: Select Interpreter → .venv\Scripts\python.exe. Для запуска через F5 установите расширения Python и Python Debugger от Microsoft, затем выберите конфигурацию Survey School. Остановите сервер в терминале перед запуском через F5, чтобы освободить порт 5000.

Если окружение уже подготовлено

В терминале проекта выполните Test-Path .\.venv\Scripts\python.exe. Если ответ True, выполните последнюю строку из блока запуска или нажмите F5. Папка .venv содержит отдельное окружение проекта. Команда -m pip install -r requirements.txt устанавливает в него Flask и Waitress, а app.py запускает сам сервис.

2. Первый опрос

  1. Нажмите «Создать опрос», задайте название, отредактируйте три готовых вопроса.
  2. Сохраните черновик и нажмите «Опубликовать».
  3. Откройте ссылку участника в приватном окне браузера. Укажите имя, заполните и отправьте ответы.
  4. Вернитесь в окно администратора → Результаты → Скачать CSV. Файл открывается в Excel.
  5. Нажмите «Закрыть», чтобы прекратить приём ответов.

После получения первого ответа структура опроса блокируется для редактирования: для следующих вопросов создайте новый опрос. Повторные ответы разрешены; имя не подтверждает личность участника.

Для первой попытки подойдёт название «Как прошло занятие?». Оставьте стартовые вопросы. В приватном окне введите вымышленное имя, напишите короткий отзыв, выберите оценку и отметьте две темы. После отправки должна появиться страница «Спасибо!». В обычном окне увидите одну строку с именем и ответами. Когда закроете опрос, обновите страницу участника и убедитесь, что форма исчезла.

Адрес с 127.0.0.1 подходит для двух окон одного компьютера. Для проверки роли участника отдельное приватное окно удобно тем, что у него своя сессия и состояние входа администратора туда не переносится.

3. Карта проекта

  • app.py — маршруты сервера, запросы SQLite, HTML-шаблоны и JavaScript конструктора в одном учебном файле.
  • requirements.txt — библиотеки проекта.
  • instance/ — автоматически создаваемые база, ключ сессии и хеш пароля. Не публикуйте эту папку в Git. Резервную копию делайте при остановленном приложении.
  • test_app.py — проверка основного сценария на временной базе.

Путь одного ответа

  1. Браузер открывает /s/… запросом GET. Flask вызывает participate, находит опрос в SQLite и проверяет статус публикации.
  2. Jinja получает список вопросов из Python и превращает шаблон в HTML. Браузер показывает текстовое поле, переключатели и флажки.
  3. При отправке браузер делает POST. Flask читает поля, проверяет токен формы и введённые значения, затем сохраняет имя и ответы в SQLite.
  4. Flask перенаправляет браузер на /thanks. Когда администратор открывает результаты, отдельный обработчик читает сохранённые записи.

Чтобы увидеть GET, POST и перенаправление, откройте в браузере инструменты разработчика (F12), выберите Сеть / Network и отправьте форму. Включите сохранение журнала при переходах, чтобы увидеть оба запроса.

Для упражнений создайте рядом файл practice.py. Запуск: .\.venv\Scripts\python.exe practice.py. После каждого законченного занятия делайте Git-коммит.

Занятие 1. Маршруты и первый ответ

Найдите app = Flask(__name__) и функцию thanks. Декоратор app.get связывает адрес с функцией; return определяет ответ браузеру. Добавьте перед блоком if __name__ следующий маршрут:

@app.get('/hello')
def hello():
    return 'Мой первый сервис опросов!'

Задание: добавьте /about с описанием проекта. Проверка: оба адреса открываются в браузере.

Строка с @ называется декоратором. При загрузке файла она регистрирует адрес во Flask. Когда браузер запрашивает этот путь, Flask вызывает функцию под декоратором. return возвращает её ответ. После изменения перезапустите сервер и откройте http://127.0.0.1:5000/hello. Затем откройте /helloo и сравните результат с 404, который браузер получает для неизвестного адреса.

Занятие 2. Данные Python и шаблоны

Изучите EXAMPLE: список вопросов, каждый вопрос — словарь. В practice.py выполните:

question = {'text': 'Нравится Python?', 'options': ['Да', 'Пока не знаю']}
for number, option in enumerate(question['options'], start=1):
    print(number, option)

В participate найдите цикл шаблона {% for q in questions %}. Python готовит данные, Jinja строит HTML. Задание: измените стартовые вопросы EXAMPLE. Проверка: новый опрос показывает новые вопросы.

Список хранит элементы по порядку, а словарь позволяет брать значения по ключам. Например, question['options'] возвращает список вариантов. enumerate(..., start=1) отдаёт номер и значение в каждой итерации. Здесь нумерация начинается с 1 для человека, а в форме проекта используется q0 для первого поля. В Jinja {{ q.text }} вставляет значение, а {% for ... %} повторяет кусок HTML для каждого вопроса.

Измените один текст в EXAMPLE, перезапустите сервер и нажмите «Создать опрос». Проверьте отдельно ранее сохранённый опрос. Его вопросы читаются из базы.

Занятие 3. GET, POST и формы

Изучите participate: GET показывает форму, POST читает request.form, сохраняет ответ и перенаправляет на /thanks. Атрибут name поля определяет ключ в request.form.

# Внутри обработчика POST:
name = request.form.get('name', '').strip()

Задание: переименуйте подпись «Представьтесь» в «Ваше имя и фамилия». Проверка: отправьте форму и найдите имя в результатах.

Подпись поля читает человек, а его name="name" использует сервер. get('name', '') берёт значение по ключу и возвращает пустую строку, если поля нет. strip() удаляет пробелы по краям. При успешном POST сервер перенаправляет на GET /thanks, поэтому обновление страницы благодарности не отправляет форму повторно.

Подробнее в руководстве MDN по HTML-формам и разделе Flask о данных запроса (англ.).

Занятие 4. Условия, функции и ошибки

def valid_name(name):
    return 2 <= len(name.strip()) <= 200

print(valid_name('Анна'))  # True
print(valid_name(''))      # False

Задание: используйте valid_name в participate. Проверка: имя из одного символа отклоняется, нормальное принимается. Проверка на сервере обязательна, даже если в HTML стоит required.

True и False — логические значения. Функция из примера сначала убирает лишние пробелы, затем проверяет обе границы длины. Прогоните её в practice.py с ' А ', ' Анна ', ' ' и строкой из 201 буквы. Сравните вывод с тем, что ожидали. В коде маршрута связь с функцией будет выглядеть как if not valid_name(name): в месте текущей проверки имени.

Подробнее в руководстве Python по условиям и функциям.

Занятие 5. SQLite и связи

Прочитайте CREATE TABLE: surveys хранит опросы; answers ссылается на опрос через survey_id. questions и payload пока хранят списки в JSON. Параметры SQL передаются через ?, а не склейкой строк.

with db() as c:
    total = c.execute('SELECT count(*) FROM answers WHERE survey_id=?', (1,)).fetchone()[0]
    print(total)

Задание: покажите на главной общее количество ответов по всем опросам. Проверка: отправка нового ответа увеличивает число на один.

id — номер записи в своей таблице. Если опрос имеет id=5, то его анкеты будут разными строками с одним и тем же survey_id=5. SELECT читает строки, WHERE выбирает нужные, count(*) считает их. В примере fetchone()[0] берёт первую колонку единственной строки результата. В (1,) нужна запятая, чтобы получился кортеж из одного параметра. Подставьте номер своего опроса из адреса «Результаты».

Для задания найдите index. Выполните рядом с запросом опросов отдельный запрос SELECT count(*) FROM answers. Передайте полученное число в page как именованный аргумент и выведите его в HTML через {{ ... }}.

Занятие 7. Вход администратора

Читайте login, admin_only и protect_forms. Пароль хранится как хеш; session хранит признак входа; CSRF-токен проверяет отправку формы из текущей сессии.

Задание: измените страницу входа, добавив приветствие. Проверка: без входа /results/1 перенаправляет на вход, а публичный опрос открывается. Не удаляйте проверки доступа при изменении интерфейса.

При первом входе login сохраняет хеш пароля. При следующем входе Werkzeug проверяет пароль по хешу. После входа Flask помещает признак admin в сессию браузера. @admin_only проверяет его перед входом в закрытые страницы. Токен CSRF решает отдельную задачу: сервер сверяет скрытое поле формы с токеном в сессии, прежде чем выполнять POST.

В обычном окне проверьте, что можете открыть результаты. В приватном откройте тот же адрес и убедитесь, что попали на страницу входа. Затем в приватном окне откройте ссылку опубликованного опроса. Для ответа пароль администратора не требуется.

Занятие 8. Конструктор

Читайте edit: данные проверяются, затем INSERT создаёт опрос, UPDATE меняет существующий. После сохранения опрос становится черновиком.

Задание: добавьте ограничение длины текста вопроса до 300 символов в серверной проверке. Проверьте короткий и слишком длинный вопрос.

На GET сервер показывает стартовые вопросы или читает сохранённые. На POST он получает название и JSON вопросов, проверяет структуру и число вариантов, а затем сохраняет опрос. Занятие 11. JavaScript

В edit найдите script: createElement создаёт блок вопроса, обработчики onclick добавляют и удаляют вопросы, onsubmit сериализует их в JSON. Основная отправка формы пока выполняется обычным POST.

Задание: рядом со стрелкой ↑ добавьте ↓ для перемещения вопроса вниз. Проверка: после сохранения порядок на публичной странице совпадает с конструктором.

5. Запуск в Docker

Сначала локально задайте пароль администратора и остановите локальный сервер (Ctrl+C). Затем в PowerShell из папки проекта:

docker build -t survey-school .
docker run -d --name survey-school -p 127.0.0.1:5000:5000 --mount "type=bind,source=$((Resolve-Path -LiteralPath .\instance).Path),target=/app/instance" survey-school

Для публичного сервера нужны HTTPS через обратный прокси, резервные копии instance и ограничение попыток входа. Не открывайте первый запуск с незаданным паролем в интернет: первый посетитель сможет создать администратора. Встроенный app.run используется только для локального обучения; контейнер запускает Waitress. Доступ другим компьютерам потребует адреса сервера и настройки firewall; localhost работает только на вашем компьютере.

docker build собирает образ по Dockerfile. docker run запускает контейнер из образа. Параметр -p связывает порт контейнера с локальным адресом Windows, а --mount подключает папку instance с уже созданной базой и ключом. После запуска откройте тот же адрес, что и при локальной работе. Для остановки используйте docker stop survey-school, для повторного запуска того же контейнера — docker start survey-school.

Подробнее в документации Docker по подключению папок (англ.).

6. Как учиться

Перед правкой сформулируйте ожидаемое поведение. Внесите одно изменение, запустите, проверьте положительный и ошибочный сценарии, сделайте коммит. После освоения материала разделите app.py на шаблоны templates/, CSS static/ и отдельный модуль базы — это следующее упражнение по организации проекта.
